# 📂 Памятка: Разница между манифестами Kubernetes и Helm (Учебный проект)

Этот конспект объясняет архитектурный переход проекта от «сырых» манифестов к пакетному менеджеру Helm и разделению ресурсов по жизненным циклам.

---

## 🛑 Проблема: Сырые манифесты (Папка `manifests/`)

В папке `manifests/` находится базовый набор ресурсов:
*   `backend.yaml` — логика приложения.
*   `postgres.yaml` — база данных.
*   `ingress.yaml` — маршрутизация трафика.
*   `config.yaml` и `secret.yaml` — настройки и доступы.
*   `backend-hpa.yaml` — автос масштабирование.

### В чем минус такого подхода?
При каждом деплое на новый кластер или в новый `namespace` приходится **вручную править данные внутри файлов**:
*   Доменные имена.
*   Теги и имена Docker-образов.
*   Учетные данные (креды).

---

## 🚀 Решение: Зачем нужен Helm?

1.  **Шаблонизация:** Helm превращает статичные манифесты в динамические шаблоны.
2.  **Конфигурация в одном месте:** Все изменяемые переменные значения выносятся в единый файл — `values.yaml`.

### 🔄 Разделение по жизненным циклам (Backend vs DB)
Мы сознательно разделяем проект на **два независимых чарта**, так как у них разная логика обновлений:

*   **`backend-api`** — обновляется постоянно (при каждом деплое новой версии кода).
*   **`postgres`** — обновляется крайне редко и осторожно, так как хранит данные.

> 💡 **Главный вывод:** Два независимых чарта = два независимых релиза (`helm upgrade`). Мы не рискуем базой данных при обновлении бэкенда.

---

## 🛠 Практика: Создание структуры

Для генерации скелета чартов используются команды:
```bash
helm create helm/postgres
helm create helm/backend-api
```

*После генерации обязательно **удаляем лишние стандартные файлы** из папки `templates/` (например, `serviceaccount.yaml`, `tests/` и дефолтный `hpa.yaml`), так как мы пишем свои.*

### 📁 Финальная структура директории `helm/`

```text
helm/
├── postgres/               # 📦 Чарт для базы данных (свой жизненный цикл)
│   ├── Chart.yaml          # Метаданные чарта
│   ├── values.yaml         # Настройки БД (пароли, порты, объем диска)
│   └── templates/
│       ├── secret.yaml
│       └── stetefulset.yaml   # StatefulSet
│       └── service.yaml   # Service
│
└── backend-api/            # 📦 Чарт для приложения (частые обновления)
    ├── Chart.yaml          # Метаданные чарта
    ├── values.yaml         # Настройки бэкенда (тег образа, лимиты, домен)
    └── templates/
        ├── configmap.yaml
        ├── secret.yaml
        ├── deployment.yaml    # Deployment 
        ├── service.yaml    # Service
        ├── ingress.yaml
        └── hpa.yaml        # Наш собственный кастомный HPA
```

📌 **Важное правило:** Каждый чарт изолирован и полностью владеет только своим набором ресурсов.
